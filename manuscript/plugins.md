# 第21章 插件与MCP：接入需要的工具和资料

前面的材料都在本地文件里。如果你要处理的资料保存在某个外部服务中，Codex还需要相应的连接。此时，安装一个合适的插件，可能比来回下载和上传更方便。

先有明确需要，再连接相应工具。插件多并不等于结果更好；你应该知道这次连接要解决什么问题，以及它会让Codex接触哪些材料。

## 插件提供什么

**插件**是一个可以安装的能力包，里面可能包含技能、连接工具和其他资源。技能说明怎样做，连接工具则提供取得资料或执行动作的通道。不是每个插件都需要外部账号，也不是每个插件都只有一个技能。[插件组成](https://learn.chatgpt.com/docs/plugins)

其中常见的一类连接叫 **MCP，Model Context Protocol**。对使用者来说，可以先把它理解为模型与外部工具交换请求和结果的一套通用连接方式。一个MCP服务可以提供查询资料、读取记录或执行操作的工具，具体能力由该服务决定。

你不必会开发MCP才能使用插件。普通入门路径是先从应用里的插件目录选择需要的能力，按提示连接；直接添加MCP服务，留到有可信服务提供明确设置方法时再做。

## 从一个只读需要开始

假设你已经在某个文档服务中保存了一份无敏感信息的测试文档，只想让Codex读出标题和第一段。这是一个容易核对的小任务，也不需要先授权它修改或分享文档。

打开桌面的 **Plugins**，搜索你实际使用的服务或需要的能力。进入详情，核对提供者、说明、支持入口和所需条件。标为 **Desktop only** 的插件需要桌面应用；不能因为网页能看到介绍，就认定所有设备都能使用。

确认合适后，使用详情中的安装加号。需要外部连接时，按提示登录相应服务：有的在安装过程中认证，有的第一次使用时才提出。看清浏览器或授权页中的账号，以及请求访问的范围，完成后回到应用。[安装与连接顺序](https://learn.chatgpt.com/docs/plugins)

安装完成，再开始一个新的Codex任务，让它使用刚装好的插件。可以直接写服务名和目标，也可以在`@`菜单中选择当前提供的插件入口。提供准确的文档链接或标题，并限定只读：

> 用刚连接的文档服务，读取我指定的测试文档。先确认标题和位置，再列出第一段文字与原文链接；不修改内容，不更改分享设置，也不发送给别人。

最后到原服务打开文档，比较结果。能返回正确的对象与内容，才说明这次连接对当前任务有效。没有外部服务账号，也不影响前面的本地文件路线；不用为了学插件而额外购买一个服务。

## 五种状态，不要混在一起

遇到「装了却不能用」，先看卡在哪一层：

| 状态 | 它说明了什么 |
|---|---|
| 已安装 | 插件包进入当前环境 |
| 已启用 | 相关技能或工具允许被当前环境使用 |
| 已登录或连接 | 外部服务认证已经完成 |
| 能访问指定对象 | 当前账号确实有这份文档或记录的权限 |
| 本次动作获准 | 这次读取、修改或其他动作符合当前授权 |

例如，你登录了一个文档账号，但资料属于另一个组织空间，仍可能没有访问权。插件安装成功，也不保证旧任务马上拥有新工具，所以官方流程要求安装后在新任务中使用。

如果只是读测试文档，不应顺便要求它搜索整个账号的所有资料。对象越明确，越容易判断请求权限是否与任务相符。

## `/mcp`帮助看连接状态

在当前任务的斜线菜单中选择 **`/mcp`**，可以查看已连接的MCP服务状态。它是检查入口，不是自动安装、登录或修复所有服务的按钮。[MCP状态与设置](https://learn.chatgpt.com/docs/extend/mcp)

需要管理直接连接的服务时，进入 **Settings → MCP servers**。列表会显示服务是否启用，以及是否需要认证；需要登录的服务使用 **Authenticate**。已有服务名称相近时，先确认要处理哪一个，不要一看到失败就重复添加。

可信服务若明确要求直接添加MCP，可从 **Add server** 开始，按照提供者给出的名称、连接类型和地址或启动方式填写，保存后使用 **Restart** 让设置重新加载，再完成需要的认证。这里可能看到Streamable HTTP或STDIO：前者连接服务地址，后者通常启动本地程序。没有必要为了普通插件使用而先掌握这些配置，更不要把来历不明的启动命令粘贴进去试运气。

网页ChatGPT与本地Codex的连接管理也不完全相同。不能因为改过电脑上的配置，就认定网页里的服务已经同步完成认证。

## 工具能做，仍要看这次该不该做

外部服务有自己的账号权限和数据处理规则；通过Codex运行的能力也受到当前任务的权限与组织要求影响。连接成功，不会把「可以读取」自动变成「可以替我发布」。

例如，读出一份文档以后可以帮你起草修改意见；真正写回原文、改变共享范围或发送给别人，则是另一类动作。提出要求时明确是草稿还是执行，出现具体批准请求时读清对象与影响。

网页或服务返回的内容也可能包含其他人的指令。它们是当前任务读取的材料，不会自动改变你给定的目标。不要因为来源通过插件进入，就把里面的每句话都当作操作命令。

## 不用了，怎样关掉

临时不用某项能力，可以先在对应管理界面检查启用状态，按需要关闭有关技能或连接工具。长期不需要的插件，在Plugins中打开详情，使用可用的 **Uninstall plugin**。组织安装或默认提供的插件，可能由管理员管理，没有个人卸载入口。

卸载插件移除的是该环境中的插件包。另行建立的MCP集成可能仍然连接，需要到对应连接管理中单独断开；如果还希望撤回外部服务对应用的授权，也应到那个服务的授权设置核对。[卸载与独立连接](https://learn.chatgpt.com/docs/plugins)

卸载不会自动收回已经发出的消息，也不会还原先前写入的外部文档。需要撤销某个结果，仍应在对应服务里处理具体对象。

插件不能使用时，按安装、启用、账号、对象权限和当前任务逐层检查。这样的排查比不断重装更容易找到原因，也能避免重复连接到错误的账号。
