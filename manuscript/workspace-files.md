# 把文件准备好，让 Codex 找到它

发照片的提醒记了两遍，买笔记本的要求又补在另一份备忘里。我们接下来要请 Codex 把这些零散信息整理成清单。开始之前，先让它找到材料，确认两边看到的是同样的内容。

[上一章](desktop-setup.md)已经认识了项目、聊天和输入框。这一章把它们用起来：把备忘所在的文件夹接进项目，开始聊天，再发出第一条要求。下一章接着整理和保存，两个章节完成同一个小案例。

## 先拿到两份备忘

打开[配套材料页](../examples/ch04-notes-to-todos/README.md)，取得「我的待办-起始材料.zip」并解压，把「我的待办」放在容易找到的位置，例如桌面。随书文件中也有这个压缩包。里面是本书自编的两份备忘，不含真实个人信息。

我们要用的是直接包含「材料」的那一层「我的待办」。文件按下面的方式存放：

| 文件夹 | 里面放什么 |
|---|---|
| 我的待办 | 「材料」文件夹；下一章还会新增「结果」文件夹 |
| 材料 | 「随手记.txt」和「补充说明.txt」两份原件 |
| 结果 | 整理后的清单；现在还没有这个文件夹 |

原件和结果分开放，发现疑问时才有依据可查。起始压缩包也先留着，需要时可以重新解压出一份原材料。

## 打开看看，认识我们要整理的内容

打开「材料」里的「随手记.txt」和「补充说明.txt」，先看内容，不修改原件。

「随手记」记了发照片、整理书桌、买笔记本、联系维修店四件事。「补充说明」补上照片选10张、笔记本要横线款等要求，也注明日期和预约尚未确定。整理时两份都要看。

## 把文件夹连接到 Codex

回到 Codex，接下来连接外层的「我的待办」：我们既要读取里面的「材料」，又要在旁边建立「结果」，所以选它们共同的外层文件夹。只把文件放到桌面，还没有告诉这次聊天应该到哪里工作。

用默认快捷键打开「打开文件夹（Open folder）」窗口：**Windows：Ctrl+O；Mac：⌘O**。选择「我的待办」文件夹，不要选压缩包或单独一份备忘。

上一章说的**本地项目**，现在就有了具体对象：它连接的是电脑里的「我的待办」。以后要回到这份工作，可以从应用中找到这个项目；要用其他软件查看材料，则仍到电脑上的文件夹中打开。项目里的聊天与文件夹里的文件，分别承担交流和保存的作用。

在这个项目里开始**新聊天（New chat）**，Windows 可用 Ctrl+N，Mac 可用 ⌘N。发送要求前，核对这次聊天选的是刚刚连接的项目，再把运行位置选为 **Local（本地）**。Local 表示直接在电脑上的当前项目文件夹中工作，所以接下来新生成的清单也应当到这里找。

发送第一条要求前，看看当前聊天是否选中了「我的待办」，运行位置是否是 Local。接下来的读取、整理和修改都会围绕这份清单进行，留在同一聊天里就可以继续，不用每读一份材料就重新开始。

连接位置有时会显示成一长串文字，例如 Windows 的 `C:\Users\demo\Desktop\我的待办`，或 Mac 的 `/Users/demo/Desktop/我的待办`。这叫**路径**，可以理解为文件或文件夹的地址：从外层位置，一层层找到「我的待办」。`demo`只是示例用户名，你的用户名和保存位置可能不同，不要照抄这两个地址。核对时看它是否指向你刚才打开备忘的那一处，而不只看末尾的文件夹名。

## 先看清它能做什么

**权限**决定 Codex 可以做哪些操作，以及何时需要批准。在输入框下方确认当前聊天使用 **Ask for approval（请求批准）**。按官方说明，这一档允许它在当前范围内读写文件、执行常规本地操作，需要额外访问时再询问。具体范围和可选模式受设置及组织要求影响。

这个名字并不表示每读一次文件、每改一行字都会再问。选定项目也不等于在所有配置下都把访问范围锁死在一个文件夹内。遇到请求时，看清它要做什么、访问哪里；看不明白先拒绝，再请它解释。Local 是工作位置，不是保密选项；使用自己的材料前，仍要确认这些内容可以交给 AI 服务处理。

## 让它读一遍，确认材料找对了

在聊天输入框里发送：

> 看一下「材料」里有哪些文件，各自记了什么。先不要改文件。

发给 Codex 的要求叫**提示词**。这里说明了去哪里看、看完告诉你什么，以及暂时不要改动。最后一句是工作要求，不会自动把权限切换成只能读取，原件仍要检查。

回复里只有「找到了两个文件」还不够。看看它能否说出照片选10张、笔记本要横线款这些细节。文件名和内容都能对应，才有理由继续；对不上，就指出具体差异，请它重新读取。这里是在确认它看到了什么，还没有让它合并清单，因此回复的排版和句子不必与原件一样。

这也是处理陌生材料时值得保留的习惯：先确认理解，再开始加工。以后资料多了，挑几条关键事实核对，能帮助你尽早发现读错文件或漏读材料的问题，不必等整份结果做完才回头找原因。

回复看完后，再从「材料」里重新打开两份原件，确认内容没变。此时还没有要求生成清单，不需要出现「结果」文件夹。现在你已经用过打开文件夹、新聊天和发送要求；下一章就在这个聊天里，把「读一读」推进到「整理并保存」。

## 没得到预期结果时

| 停在了哪里 | 可以先做什么 |
|---|---|
| 解压后层级对不上 | 找到里面直接有「材料」的「我的待办」 |
| 备忘打开后是乱码 | 关闭文件，不要覆盖保存；回材料页直接查看两份原文作对照，再重新取得压缩包，在新位置解压。若页面文字正常而本地仍不可读，先保留这份原件，记录所用文本软件和系统后求助，不凭乱码让AI猜内容 |
| 快捷键没有反应 | 确认在Codex入口；用Windows Ctrl+,或Mac ⌘,打开设置，在Keyboard Shortcuts中搜索Open folder，查看当前绑定，再执行打开文件夹 |
| Codex说「材料」不存在 | 先请它报告当前工作位置及其中的文件名，把路径与电脑上的「我的待办」对照；选错时重新用Open folder选正确目录，并在正确项目开始新聊天，再发只读请求 |
| 能找到文件，讲出的内容却对不上 | 指出两份原件里的具体文字，请它重新读取；不要把补写的猜测当作找到了材料 |
| Windows提示需要初始设置 | 回[第2章Windows首次设置](desktop-setup.md)处理沙箱设置，再回本章继续 |

备忘用哪一个软件打开，并不影响它是不是这份材料。只要能正常读到原文，就可以继续；不必为了与别人截图相同而更换文本软件。
