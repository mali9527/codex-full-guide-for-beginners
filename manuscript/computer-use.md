# 第23章 电脑操作：让Codex操作其他应用

有些内容可以直接从文件里读出来，有些只需要看一张截图，还有些必须打开应用才能检查。例如，你想知道一份清单在正在使用的文本软件里是否显示完整，单看文件内容不一定能回答窗口里的问题。

**Computer Use，电脑操作**，让Codex查看和操作应用的图形界面。它可能点击、输入或切换窗口，因此会影响文件夹以外的应用状态。使用之前，先把目标应用、动作范围和结束条件说清楚。

## 先判断是否真的需要操作应用

如果只要合并两份文本，前面的文件路线已经足够。如果只是希望它解释一张界面，Appshot或截图也可能够用。需要它实际进入某个窗口、查看菜单或验证界面状态时，再考虑Computer Use。

应用有专门插件或结构化连接时，也可以先考虑那些工具。通过明确的接口读取一份记录，通常比模拟鼠标逐页寻找更容易重复。只有问题确实依赖视觉或界面动作时，操作应用才解决了额外的问题。[电脑操作的用途](https://learn.chatgpt.com/docs/computer-use)

本章从一个只读动作开始：查看你已经打开的自编清单，确认其中一项是否在窗口里完整显示。它不发送消息、不修改账号，也不替你处理清单中的现实事务。

## 先安装并启用功能

官方当前在支持地区为Mac和Windows桌面上的Work与Codex提供Computer Use，具体仍受账号、版本和组织设置影响。在桌面选择Codex，进入 **Plugins → Computer Use**，按提示选择 **Install plugin**；出现 **Enable** 时启用，并确认对应的服务与技能开关打开，再使用 **Try now** 开始。[设置Computer Use](https://learn.chatgpt.com/docs/computer-use)

接着到 **Settings → Computer use** 查看应用访问设置。安装插件只是准备能力，还没有替你批准对所有应用的访问。

Mac需要按系统提示提供屏幕录制和辅助功能权限：前者让它看到应用，后者让它点击、输入和导航。如果不能读取或控制，到 **系统设置 → 隐私与安全性** 检查Codex Computer Use对应的这两项授权。系统和组织要求仍由你处理，Codex不能替你批准系统安全请求或完成管理员认证。

Windows的条件不同。目标应用必须在活动桌面可见，操作期间它会使用前台鼠标与键盘，不能一边让它控制同一桌面，一边照常用鼠标处理其他事。需要持续运行时，也不能假定锁屏以后仍会按原方式工作。[Windows前台与Mac权限](https://learn.chatgpt.com/docs/computer-use)

## 应用批准是另一层选择

即使系统权限已经开了，Codex要使用具体应用时，仍会提出相应的应用访问请求。核对应用名称，确认它正是这次要查看的软件，再决定允许。

**Always allow**表示以后可继续使用该应用而不重复询问，不只是允许眼前这一次。刚开始可以按单次请求处理，等熟悉实际范围以后再决定是否保留长期允许。已保存的允许应用可以在Settings → Computer use中查看和移除。

第7章的沙箱与权限模式仍然有作用，但不能代替这里的系统授权和应用批准。切换Full access也不等于系统已经允许读取屏幕，更不应该成为每一次连接问题的通用解决方法。

## 开始前，把窗口与停止方式确认好

先用平时的文本软件打开自己的「待办清单-v2.txt」，核对文件名，把目标窗口准备好。Windows上尤其要保持它在活动桌面可见。

第一次交出应用控制之前，先在自己的版本中确认任务的停止控制在哪里，以及使用以后会显示什么状态。没有找到或不确定时，先使用第9章的文件或Appshot路线，不要从无法及时收回的界面操作开始。

普通补充可以用第8章讲过的Steer送进当前运行，例如要求「停止当前操作，不再点击或输入」。这种消息需要被处理并得到确认，不是立即中断正在进行动作的保证。收到不再操作的确认以后，再接手检查；不要把一句已发送的停止要求，当成控制已经结束。

## 给出一个小范围要求

在新任务中，使用可用的 **`@Computer`**、具体应用的`@`入口，或者直接说要使用Computer Use。把下面的应用名称替换成你实际打开的文本软件：

> 请用Computer Use查看我已经打开的文本软件中「待办清单-v2.txt」窗口。先确认窗口和文件名，再查看「联系维修店」那一项是否完整显示，只报告看到的文字和是否被遮挡。不要输入、修改文件或打开其他资料；确认完就结束。

先确认对象，再看指定内容，结束条件也很明确。如果它报告的是另一个窗口，立即要求停止并重新核对，不要继续发「再往下看看」之类依赖错误对象的指令。

Mac在适用情况下可以进行某些后台应用操作，但不代表所有应用都能无干扰地完成。Windows使用前台时，等任务完成再操作同一桌面，避免你的输入与它的输入混在一起。更复杂的跨应用流程，应在熟悉这些条件后再考虑。

## 看真实应用里的结果

本例不要求修改，所以先检查目标窗口仍是正确文件，内容没有被编辑，再比较它报告的文字。它能说出清单内容，不一定证明实际查看了窗口；留意任务是否真正使用了应用工具，以及返回结果是否对应当前显示状态。

以后若授权修改应用中的内容，还要看有没有真正保存。某些修改可能只留在应用内部，暂时没有写到磁盘；项目的改动面板也未必能立即显示所有应用变化。需要交付文件时，按第10章重新打开实际文件核对。[应用状态与保存](https://learn.chatgpt.com/docs/computer-use)

查看某个窗口，并不意味着它能自动操作任何程序。官方明确限制通过Computer Use自动操作终端应用或ChatGPT自身，也不能用它批准电脑的安全与隐私授权。遇到这样的限制，应该回到任务真正需要的工具，不能让它改用另一个界面绕开。

## 结束任务与撤回授权不同

一次查看结束，只表示这一轮不再操作。如果以后不想让它自动使用某个应用，到 **Settings → Computer use → Always allow** 移除该应用，下次再访问时重新判断。

想暂停使用整项能力，可以在插件管理中关闭相应服务与技能。Mac还可以在系统隐私设置中撤回屏幕录制或辅助功能授权；这与移除某个应用的长期允许不同，可能影响多个相关操作。

这些动作都不会自动恢复先前已经修改的文件。要撤销某项结果，需要在实际应用或已保存副本中处理具体变化。关掉插件与找回旧内容，是两件事。

应用不受支持、授权未完成或停止方式不清楚时，文件、截图和快照仍然可用。先用自己能够判断和控制的范围完成工作，比把所有应用都接进来更容易建立可靠的使用习惯。
