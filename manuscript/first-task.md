# 得到第一份可以检查和保存的结果

上一章，Codex 已经找到了「随手记」和「补充说明」。现在，两份备忘都在眼前，可以请它把分散的信息理到一起了。发照片这件事记了两遍，数量写在另一份备忘里；整理书桌只记了要做，还没有定日期。我们想得到一份清单，打开就知道有哪些事、有什么要求。

这几件事不多，自己也能整理。本章先用小份材料，是为了让每一个变化都看得清楚：Codex 从哪里读到信息，合并后有没有遗漏，保存的文件在哪里，以后又怎样继续改。走完这一次，你再交给它更多资料，也知道该检查哪些地方。

先看清单里的一项。原来的两份备忘分别写着：

> 2026年10月6日18:00前，把上次出游的照片发给同行的朋友。
>
> 给朋友发照片，选10张就好，不用发整个相册。

本书配套的第一版清单中，这一项是：

> 1. 待办｜给同行的朋友发上次出游的照片。
>    截止时间：2026年10月6日18:00前。选10张，不用发送整个相册。

做什么、什么时候做完、要选多少张，现在都放在一起了。我们还要让这份清单留在电脑里，过几天想补一条或改一处时，能接着用。备忘还没准备好的话，先按[上一章](workspace-files.md)找到两份文件，再回到这里。

## 请它整理成一份能留下来的清单

继续使用上一章已经读过备忘的那个聊天。两份文件的位置已经确认，这次可以直接告诉它要怎样整理、保存在哪里：

> 请把「材料」里的两份备忘整理成一份待办清单。同一件事只列一次，把补充要求放到对应事项下面。
>
> 保留写明的日期、时间和数量；没有确定的时间就照实说明，不要替我安排。每项先标为「待办」。只整理清单，不代办其中的事情。
>
> 在「我的待办」里新建「结果」文件夹，保存为「待办清单-v1.txt」，原材料保留不动。完成后告诉我文件放在哪里。

这里没有要求它替你安排一天的生活。发照片要选10张，这是备忘里已有的要求；整理书桌哪天做，还没有决定，就先留下这个空白。让它把已知的事情说明白，比补出一份看起来很完整、其实混了猜测的计划更有用。

保存位置也在这段话里说清楚了。「材料」继续放原件，「结果」放新清单，以后回头核对，两边都能找到。文件名里的 `v1` 是我们给第一版起的标记，意思是「版本1」；它只是名字的一部分，不会自动替我们保存每次修改。

发出去后，等它完成这次处理并回复。我们要确认两件事：清单整理了，文件也存下来了。只在聊天里看到一段文字，还不能说明保存已经完成；接下来要到文件夹里打开看看。

## 打开清单，看它有没有理解你的意思

回到电脑里的「我的待办」，打开新出现的「结果」文件夹，找到「待办清单-v1.txt」。用上一章查看备忘的文本软件打开它。以后离开这次聊天，你也要能从这里找到清单，所以这一步值得自己走一遍。

Codex 可能会用一长串文字说明保存位置。这叫文件的**路径**，也就是文件地址。比如，下面两行分别是Windows和Mac上的写法示例，其中的`demo`只是示例用户名：

- Windows：`C:\Users\demo\Desktop\我的待办\结果\待办清单-v1.txt`
- Mac：`/Users/demo/Desktop/我的待办/结果/待办清单-v1.txt`

你的用户名和保存位置可能不同，不用照抄这两行。它们只是把「哪个文件夹里面还有哪个文件夹」写成了一串地址。先按自己选的位置逐层打开就够了；需要 Codex 帮你找时，让它把地址解释成文件夹层级。

配套的[完整清单](../examples/ch04-notes-to-todos/演示结果/待办清单-v1.txt)有四件事。你的措辞可能不同，我们拿原备忘对照几个具体地方，就能判断有没有整理到位。

先看发照片。它应该只出现一次，截止时间仍然是2026年10月6日18:00前，数量是10张。两条提醒合并之后，这些要求也要一起留下来；把「18:00前」变成「18:00开始」，意思就变了。

再看还没定下来的事情。整理书桌没有日期，自行车也还没预约。清单应该保留这两个未确定的状态。空着的地方提醒你还要做决定，不需要为了让每一行都整齐，就替自己安排一个时间。

最后看看有没有漏事：发照片、整理书桌、买笔记本、联系维修店，都要在。笔记本还得是横线款。这些信息你已经在原件里看过，不需要懂代码，也能判断它有没有理解你的意思。

如果漏了照片数量，可以直接指出原文在哪里。下面是遇到这种情况时的纠正示例：

> 发照片这一项漏了数量。「补充说明.txt」里写的是选10张，请补到对应事项里，其他内容保留。

然后关掉之前查看清单的窗口，再从文件夹打开这一份，检查有没有改对。也回到「材料」里看一眼，两份备忘应当仍在、内容没变。起始压缩包里留着原件，有疑问时，可以解压到另一个位置对照。

## 做完一件，就让清单跟着更新

清单留在电脑里以后，事情有了变化，就能继续改它。假设现在笔记本已经买好了，我们希望把这一项改成「已完成」。这是演示中的一条新消息，不是原备忘里已经写过的事。

在刚才的聊天里接着说：

> 笔记本已经买好了。请把这一项标为「已完成」，其他内容保持不变。
>
> 另存成「待办清单-v2.txt」，仍放在「结果」文件夹，保留v1和两份原材料。

这里的**另存**，和办公软件里的「另存为」是同一个用意：用另一个文件名保存修改后的内容，同时留下原来那份。`v2`表示第二版。我们这次特意保留两版，方便打开比较，看看它是不是只改了要求的那一处。

配套的第二版清单中，对应的一行变成了：

> 3. 已完成｜买一本横线纸质笔记本。

打开「结果」，应当能找到 `v1` 和 `v2` 两份清单。第一版这一项仍是「待办」，第二版改成了「已完成」，其他事情保持原样。[第二版文件](../examples/ch04-notes-to-todos/演示结果/待办清单-v2.txt)也放在配套目录的「演示结果」里，供你对照；你自己电脑上保存的位置仍是「结果」。

等你熟悉这种修改方式以后，可以根据需要决定继续更新同一份文件，还是另留副本。提出要求时说明白，再打开检查一次，就知道修改有没有落到文件里。

## 下次要用，知道去哪里找

把查看清单的窗口关掉，再从「我的待办」进入「结果」，重新打开「待办清单-v2.txt」。那条「已完成」还在，才说明你看到的是保存后的文件。

下次想看看还有什么没做，直接打开它就行。又想起一件事，或者某个日期终于定下来了，就回到原来的聊天，告诉 Codex 要更新哪份清单、加上什么信息。两份原备忘还留着，整理后的清单也有了自己的位置。

## 没得到预期结果时

| 停在了哪里 | 可以先做什么 |
|---|---|
| Codex说找不到备忘 | 回上一章检查项目连接的位置，请它列出看到的文件名，再继续整理 |
| 聊天里有清单，文件夹里没有 | 请它保存为「结果」里的「待办清单-v1.txt」并说明位置；若报告不能保存，先看具体原因 |
| 等待中出现权限请求 | 查看它准备做的操作是否符合这次要求；看不明白先拒绝，再请它解释 |
| 清单漏了一件事或改错了时间 | 指出原文件和对应文字，请它修改，然后重新打开文件核对 |
| 修改后只找到一份清单 | 先确认是否保存在不同位置；若第一版确实被覆盖，重新生成不能当作找回原版 |
| 只是查看，关闭时却询问是否保存 | 先取消关闭，看看是否不小心改了文字，确认后再决定是否保存 |

本章的案例选择参考了已有教程的教学设计，具体作用见[参考来源与致谢](../参考来源与致谢.md)。备忘、提示词、清单和讲解均由本书独立编写。
