# 得到第一份可以检查和保存的结果

> 样章初稿。配套文件已完成本地读写核对，Windows 与 Mac 的完整界面路径仍待实测。

第一次用 Codex 做事，我们先把目标定得具体一点：读几份材料，整理出一份简报，放进电脑里的文件夹。做完之后，你能找到它，知道里面的信息从哪里来，也能说清楚要改什么。

本章用的是一组虚构的社区活动资料。活动叫“旧书交流会”，时间、场地和物品分别写在三个文件里。我们要把这些零散信息整理成给筹备人员看的简报。材料很短，检查时不用懂代码，只要回到原文件看一眼。

## 先认清材料放在哪里

从[配套材料页](../examples/ch04-first-result/README.md)取得“活动筹备-起始材料.zip”，把它保存到电脑。文件名末尾的 `.zip` 表示这是一个压缩包，几份文件被装在一起，方便下载。要先解压，才能把里面的普通文件夹交给 Codex 使用。

- **Windows**：在文件资源管理器里找到压缩包，右键选择“全部解压缩”（有的版本显示“全部解压”），打开解压后的文件夹。
- **Mac**：在访达，也就是平时查看文件的 Finder 中找到压缩包，双击解压，再打开得到的文件夹。

解压软件有时会多套一层同名文件夹。向里面打开，找到名叫“活动筹备”、里面直接有“材料”文件夹的那一层。把这份“活动筹备”放到你记得住的位置，例如桌面。后面我们处理的就是它。

打开“材料”，应当看到三份文件：

| 文件 | 里面有什么 |
|---|---|
| 活动安排.txt | 活动日期、时间、预计人数和活动方式 |
| 场地说明.txt | 房间位置、场地使用时间和提供的设施 |
| 物品清单.txt | 组织者准备什么、参加者自带什么 |

`.txt` 是文件的扩展名，也就是文件名末尾用来标明类型的部分。这里表示纯文本文件，主要保存文字，不带复杂排版。有的电脑会隐藏扩展名，只显示“活动安排”。这并不表示文件少了什么，也不用再给它手动补上一个 `.txt`。

我们先打开“活动安排”看看。Windows 可以用记事本；Mac 可以用“文本编辑”。如果双击后打开的是别的软件，也可以在文件上点右键，通过“打开方式”选择这两个应用之一。你应该能读到“2026年10月17日”和“14:00—15:30”。能看到这些文字，就说明材料已经找到；如果看到一串乱码，先关掉文件，不要保存覆盖，到配套材料页重新取得原件。

## 让这次任务用到这份材料

在桌面应用里选择 **Codex**，通过打开文件夹的入口选中刚才的“活动筹备”。我们把连接到电脑文件夹、用于组织相关对话的项目称为**本地项目**。本章只连接这一份资料夹，便于知道文件从哪里来、结果到哪里去。

如果已经建好了项目，可以在项目菜单里选择 **Edit project（编辑项目）**，用 **Add folder（添加文件夹）**连接“活动筹备”。不要只给项目取同样的名字：名字相同，不代表它已经连接到那个文件夹。如果项目已经连接了其他工作资料，另用一个只连接本章材料的项目更容易核对。[官方项目说明](https://learn.chatgpt.com/docs/projects)

从这个项目开始一次 **New chat（新对话）**，运行位置选择 **Local（本地）**。这里的“本地”表示直接在电脑上的项目文件夹里处理文件。书里把围绕同一件事持续进行的这段对话称为一个**任务**。我们接下来写简报、检查和修改，都留在这次任务里。[官方桌面入口](https://learn.chatgpt.com/docs/app) · [运行位置说明](https://learn.chatgpt.com/docs/environments/modes)

在输入框中写：

> 请查看活动筹备文件夹里的材料文件夹，告诉我里面有哪些文件，每份讲什么。先不要创建、修改或删除文件。如果找不到，请告诉我目前看到的文件夹名称。

这段话就是**提示词**：我们交给 Codex 的要求，用普通中文写就可以。这里先让它认材料，是为了确认双方说的是同一个地方。

正常情况下，它应当列出刚才那三份文件，并说明各自内容。措辞可以不同，文件名要对得上。如果它找不到材料，先回到项目里检查连接的文件夹；也可能是解压后多套了一层。确认“活动筹备”里能直接看到“材料”后，再请它重读一次。不要在它尚未找到文件时继续要求写简报。

界面中的**权限**决定了 Codex 可以做哪些操作、哪些操作需要征求同意。本章建议使用 **Ask for approval（请求批准）**。按官方说明，这种模式允许它在当前工作范围内读写文件；超出范围或需要联网时再请求批准。因此，读取这三份材料不一定每次都弹出询问。[官方权限说明](https://learn.chatgpt.com/docs/permission-modes)

如果出现申请，先看它要访问的位置和要做的事情，确认是否与本章材料有关。我们正在做的只是读取文字、保存简报；无法判断的申请可以先取消，让它解释用途。提示词里的“不要修改原材料”是任务要求，仍需要事后检查是否遵守。

## 把要求说到能保存为文件

材料找对之后，在同一次任务里继续输入：

> 请读取材料文件夹里的三份文件，为旧书交流会写一份给筹备人员看的简报。
>
> 按“时间和地点、参加者需要知道的事、组织者要准备的事、待确认事项”四部分写，文字简短、信息完整。
>
> 把结果保存到活动筹备文件夹内新建的结果文件夹中，文件名叫“活动简报-v1.txt”。不要修改或删除原材料。
>
> 材料没有说明的事情不要猜，放进待确认事项。完成后告诉我新文件保存在哪里。

这里说清了四件事：读哪些材料、写给谁看、内容怎么组织、文件保存在哪里。“待确认事项”也有实际用处。原材料没有报名联系人，简报应该把这件事留下来，不能为了看上去完整就编一个名字。

文件名里的 `v1` 是我们给第一版起的标记，意思是“版本1”。它只是文件名的一部分，方便稍后辨认；不会让软件自动保留所有历史修改。

发送后，等这一轮处理结束。如果 Codex 只在对话里贴出了一篇文字，还没有说明保存位置，可以接着说：

> 请把刚才的简报实际保存成文件，放到活动筹备里的结果文件夹，文件名为“活动简报-v1.txt”。保存后告诉我文件的位置。

它如果表示不能写入，先请它说明原因。文件夹未连接好、当前权限不允许写入，都需要解决相应的问题；反复说“继续”不会让这些条件自行具备。

## 到文件夹里检查结果

切回 Windows 的文件资源管理器，或 Mac 的访达，打开“活动筹备”。这时应当多出一个“结果”文件夹，里面有“活动简报-v1.txt”。打开它，检查文字是否已经写进去。

Codex 也可能给你一个文件链接，点开后可以查看。即使你已经在应用里看过内容，这一步仍然要认清它在电脑里的位置，以后才能自己找到。[官方文件工作说明](https://learn.chatgpt.com/docs/artifacts-viewer)

如果它报出的是一长串位置，先不用记里面的符号。**路径**就是文件的地址，告诉你它在哪些文件夹里面。本例只需记住这一层关系：“活动筹备”里面的“结果”，里面的“活动简报-v1.txt”。看不懂时可以让它用这种逐层打开文件夹的方式说明。

本次写作演示中，保存下来的简报有这样一段：

> 活动日期：2026年10月17日。
> 活动时间：14:00—15:30；工作人员13:30到场，16:00前完成整理并离场。
> 地点：青禾社区活动室，二层203室。
> 预计参加20人，场地座位上限24人。

这是本次文件操作演示的实际结果节选；[完整第一版](../examples/ch04-first-result/演示结果/活动简报-v1.txt)放在配套材料中。你得到的句子可能不同，下面这些事实需要相同。

**先核对时间。** 把“活动安排”和“场地说明”与简报放在一起看。14:00是活动开始时间，13:30是工作人员到场时间；15:30活动结束，16:00前要整理好并离场。这几个时间都正确，筹备人员才不会把场地可用时间当成活动时间。

**再核对地点和人数。** 房间是二层203室，预计参加20人，座位最多24人。“预计来多少人”和“最多能坐多少人”是两件事。数字都出现在原材料里，也可能被放错位置，所以不能只扫一眼有没有这些数字。

**最后看物品和缺项。** 姓名贴24张，签字笔6支；参加者自带旧书和水杯。场地有饮水机，但没有一次性水杯，也不安排投影展示。报名联系人尚未确定，结果里应当保留“待确认”。

如果其中一项有误，把原材料、错误和正确内容一起说清楚。例如下面是**错误出现时的纠正示例**，不表示本次演示实际发生过这个错误：

> 简报把预计参加人数写成了24人。请核对材料里的“活动安排.txt”：预计参加20人，24人是场地座位上限。请修正简报中对应的一句，其他信息不要改。

修改后，再打开文件确认这一句。不要只看聊天里那句“已经修好了”。同时回到“材料”文件夹，确认三份原文件还在，内容与最初相同。配套压缩包保留着原件，有疑问时可以重新解压到另一个位置对照。

## 改一处，并把第一版留下来

现在我们给参加者增加一条到场提醒。继续在同一次任务里说：

> 请根据活动简报-v1.txt 另存一份“活动简报-v2.txt”，仍放在结果文件夹。v1 保留不动。
>
> 只在“参加者需要知道的事”里增加一句：请参加者提前10分钟到场。请算出具体到场时间并写清楚，活动开始时间仍是14:00。
>
> 其余内容保持不变，不修改材料文件夹。完成后告诉我改了哪一句，以及新文件在哪里。

**另存一份**，就是用另一个文件名保存修改后的内容，同时保留原文件。这里把第二版叫 `v2`。如果只是让它“修改这个文件”，原文件可能直接变成修改后的内容；提前说清楚要保留第一版，以后才方便比较。

这次保存的第二版增加了这样一句：

> 请参加者于13:50到场，比14:00的活动开始时间提前10分钟。

回到“结果”文件夹，现在应当看到 `v1` 和 `v2` 两份文件。分别打开，核对第二版多了这句提醒，第一版没有；活动仍然14:00开始，工作人员仍然13:30到场，其余信息没有跟着变化。[本次演示的第二版](../examples/ch04-first-result/演示结果/活动简报-v2.txt)也可以查看。

“提前10分钟”是这次新增的要求，原材料里没有。我们让它只出现在新简报中，没有让 Codex 顺手回改原始资料。以后回头看，就能分清哪些来自最初材料，哪些是后来决定加上的。

## 关掉以后，还找得到吗

关掉刚才查看文字的窗口，再从“活动筹备”进入“结果”，重新打开“活动简报-v2.txt”。如果没有手动改过文字，却出现了是否保存的询问，先取消关闭，确认发生了什么，不要为了退出随手覆盖文件。

重新打开后，确认13:50的提醒仍在。这说明你找到的是已经保存到电脑上的第二版。下次想看简报，可以直接打开这个文件；如果还要让 Codex 接着修改，再回到原来的任务，说明要改哪一版、保留哪一版。

这一章完成的工作很小，但过程是完整的：材料有出处，简报有位置，内容经过核对，修改前后也能比较。以后处理更长的文档，仍然需要这些判断。

## 卡住时，先看停在哪一步

| 看到的情况 | 下一步 |
|---|---|
| Codex 说找不到材料 | 检查本地项目连接的是不是“活动筹备”，里面是否直接有“材料”；请它列出当前看到的文件名 |
| 对话里有简报，文件夹里没有 | 请它实际保存文件并说明位置；写入失败时，先读它报告的原因 |
| 找到了文件，信息不对 | 指出对应原材料和具体错误，请它修正后重新打开核对 |
| 修改后只剩一份文件 | 先确认两份文件是否被保存到不同位置；若确实覆盖了第一版，就如实记为没有保留，下一次先另存再改，不把重新生成当成找回原版 |
