# 第5章 账号与额度：看懂自己正在用什么

第一次文件任务做完以后，你可能想知道：为什么有时可以继续，有时却提示额度不足？为什么同样发了一句话，消耗差别很大？先看当前账号和限制的具体名称，比根据等待时间猜测更有用。

这一章不讨论买哪种套餐。我们沿用已经能登录的付费账号，只把使用时会遇到的身份、用量和限额看明白。

## 先确认当前是哪一个账号

在应用的个人菜单里核对当前登录身份。如果你同时有个人账号和组织提供的工作区，还要确认这次进入的是哪一个。电脑上保存的「我的待办」是本地项目；账号所属的工作区则与可用功能、组织要求和用量规则有关。两个地方都可能出现「工作」之类的名称，却不能互相代替。

例如，同一台电脑上切换了账号，原来能看到的某个模型或插件不一定仍然可用。此时先核对身份与工作区，再查该功能的条件，不要急着重新安装应用。组织账号里灰色的选项，也可能来自组织限制，需要向管理员确认。

本书使用的是ChatGPT账号登录。另一种登录方式叫API key，主要用于按开发平台的规则使用服务。它与当前账号的订阅额度不同；学习本书不需要为了遇到一次限额提示就申请密钥、切换登录方式。

## 到哪里看剩余用量

打开[官方用量页面](https://chatgpt.com/codex/settings/usage)，必要时完成登录，并核对浏览器中的账号与应用一致。看页面时，先读每块信息的名称，再读数字：它说的是哪个产品或额度范围、已经用了多少还是还剩多少、什么时候重置。

假设某块信息写着「剩余40%」，意思是在这块信息所对应的范围里还剩四成；如果写的是「已用40%」，剩下的就是六成。这里的数字只是读法示例，不是本书替你查询到的余额。不要只记一个百分比，离开它旁边的标签以后，数字很容易被读反。

页面可能同时列出较短时间窗口和每周限制。**窗口**就是计算某一段时间内用量的范围。一个窗口还有剩余，不等于其他适用的限制也有余量；某一项重置了，也不代表所有计数都同时归零。重置时间直接看当前账号页面，不按安装日期或自己上次打开应用的时间推算。

官方给出的「每五小时大约多少条消息」属于估计，不能当作每个人都能发送的固定条数。部分组织采用不同的额度或credits规则，不能把别人的截图当作自己的限额表。

## 一条消息，为什么没有固定消耗

第4章的一条要求，可能让Codex读两份备忘、写一份清单、再回头检查。你只发了一条消息，实际处理却包含好几个环节。另一条「把还书放第一项」只需处理很短的内容，两者不能简单按一条对一条比较。

模型处理信息时使用的计量单位叫 **token**。输入的要求、读入的材料、聊天历史、工具返回的信息以及输出，都可能计入处理量。token与字数不一一对应；你现在不需要换算，只要知道它衡量的范围比「我刚打了多少字」更大。

**Credits**是适用账号用于计量和支付使用量的额度单位。它与token也不是同一个数：不同模型、速度设置和处理方式，对应的消耗规则可能不同。用量页面中的百分比、credits余额和某次任务的token数量，各有各的含义，不宜直接相除，推算还可以做多少次工作。

Work与Codex共享使用量。长任务、较多材料、更高的推理投入，以及工具使用等因素都可能影响消耗。即使两条请求看起来差不多，实际读取与处理过程不同，用量也可能不同。[官方用量说明](https://learn.chatgpt.com/docs/pricing)

## 当前任务里也能查状态

回到Codex的当前任务，在输入框键入 `/`，从菜单选择 **`/status`**。这是使用应用提供的命令，不是在终端里输入。当前环境提供该命令时，它会显示任务标识、上下文使用和限额等状态信息。

其中**上下文使用量**表示这次交流中可供模型处理的信息占用情况，第13章会展开。它与账号额度分别回答两个问题：一个是这次交流装进了多少信息，另一个是当前账号还能使用多少资源。看到其中一个接近上限，不要立刻认定另一个也已经耗尽。

`/status`也不是成果进度表。它不能告诉你清单是否四项齐全，或文件有没有保存。任务状态可以帮助判断为什么不能继续，成果检查仍要回到文件和原材料。

## 出现限制时，先分清是哪一种

遇到提示后，先保留已经产生的成果和错误信息。若还在运行，先看当前轮是否继续处理，不要反复发送同一条请求；若已结束，再决定怎样接续。

| 看到的情况 | 先核对什么 |
|---|---|
| 用量达到上限 | 当前账号用量页面对应的窗口与重置时间 |
| 某个模型不可选 | 账号、组织要求、客户端版本与该模型的开放条件 |
| 一直等你批准或回答 | 回到任务处理那条请求，这不等于额度不足 |
| 文件找不到或保存失败 | 当前项目、文件位置和具体错误，先别归因于账号 |
| Credits不足或出现额外用量提示 | 读清对应范围与当前账号规则，再决定是否继续 |

换模型可能改变后续消耗，但不能据此保证绕过已经触及的限制；换一台电脑也不等于换了一份账号额度。若暂时不能继续，可以先保存当前文件名、已经完成的部分和下一步要求，等条件恢复后接着做。

## 怎样减少没有必要的消耗

先让任务范围与需要相符。例如只想检查清单有没有漏事，就提供两份备忘和当前清单，要求列出差异；不必顺便让它搜集待办管理方法、推荐软件、重新设计排版。多做的部分没有帮助，即使做得不错，也会增加阅读和检查的负担。

材料同样如此。给出相关文件和版本，比让它在一大片目录里猜哪份是最新版更直接。需要深入比较的工作，可以使用较强设置；要求已经很明确的小改动，则先看当前设置能否做好。下一章就从这个判断出发，讲模型与Effort怎样选。
